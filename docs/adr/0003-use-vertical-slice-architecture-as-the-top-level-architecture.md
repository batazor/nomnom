# 3. Использовать Vertical Slice Architecture как архитектуру верхнего уровня

Date: 2026-10-24

## Status

Accepted

## Context

Каждый bounded context содержит несколько самостоятельных сценариев, которые будут развиваться с разной скоростью. Организация верхнего уровня по горизонтальным техническим слоям разносит обработку одного сценария по разным частям проекта и увеличивает связанность изменений.

## Decision

Использовать Vertical Slice Architecture как архитектуру верхнего уровня внутри каждого bounded context. Код организуется по фичам и сценариям: обработка запроса, валидация, координация и проверки одного сценария располагаются вместе.

Горизонтальные технические слои не определяют основной каркас. Общие доменные модели и инварианты переиспользуются внутри контекста без копирования по отдельным vertical slices.

## Consequences

Изменения одного сценария становятся локальнее, а его поведение проще находить, проверять и развивать независимо. При этом потребуется следить, чтобы общие доменные правила не дублировались между срезами, а выделение переиспользуемых компонентов не превращало структуру обратно в набор горизонтальных слоёв.
