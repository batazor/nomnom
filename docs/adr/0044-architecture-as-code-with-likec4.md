# 44. Описывать архитектуру сервисов моделью LikeC4

Date: 2026-10-31

## Status

Accepted

## Context

Архитектура nomnom описана текстом в ADR, README контекстов и `ops/kind/README.md`. Общей схемы нет: чтобы понять, кто кого вызывает, какие процессы есть у контекста и кто читает топик, приходится собирать ответ из нескольких документов и манифестов. Sequence diagrams в README показывают отдельные сценарии, но не связаны между собой: один и тот же сервис на каждой схеме описан заново.

Нужна одна модель, из которой строятся схемы разного уровня, и которая лежит в репозитории рядом с кодом и правится в том же изменении.

## Decision

Архитектуру сервисов описывать моделью [LikeC4](https://likec4.dev/) в `docs/architecture/`.

- Модель одна: элементы и связи задаются один раз в `model.c4`, схемы и сценарии только ссылаются на них.
- Модель описывает текущее состояние. Нереализованное, в том числе стратегия расширения [ADR 41](0041-cell-based-architecture-with-control-plane.md), в неё не входит.
- Уровень детализации — процессы, хранилища, gateway и брокер. Слайсы и use cases остаются в README контекстов; модель ссылается на них и на ADR.
- Связи типизированы по транспорту (`grpc`, `kafka`, `cdc`, `temporal` и другие), чтобы отличать синхронные вызовы от событий.
- Версия LikeC4 закреплена в `LIKEC4_VERSION` в `Makefile`. Запуск — `make arch-dev`, проверка — `make arch-validate`, через `npx`, без `package.json` и зависимостей в репозитории. Нужен Node.js 22 или новее, как для `boundaries/ui`.
- CI модель не проверяет ([ADR 30](0030-ci-is-described-but-runs-only-on-demand.md)): проверка выполняется локально.
- Изменение, которое добавляет процесс, хранилище, топик или синхронную связь между контекстами, правит модель. Прежние sequence diagrams в README use cases остаются: они подробнее и привязаны к своему сценарию.

Рассмотренные варианты:

- **Structurizr DSL** — та же идея C4-модели, но нужен JVM или контейнер, а схемы не обновляются в браузере при правке так же просто.
- **Mermaid в Markdown** — без модели: каждая схема описывает элементы заново и расходится с остальными.
- **Рисованные схемы (draw.io и подобные)** — плохо читаются в diff и не проверяются.

## Consequences

Есть одна точка входа в архитектуру со схемами от Landscape до процессов контекста и сценариями. `arch-validate` ловит ссылки на несуществующие элементы и синтаксические ошибки.

Цена: модель поддерживается вручную и не сверяется с кодом и стендом автоматически, поэтому может устареть. При расхождении источник правды — код и `ops/`, а не модель. Появляется ещё один DSL, а `make arch-*` при первом запуске скачивает пакет из npm.
