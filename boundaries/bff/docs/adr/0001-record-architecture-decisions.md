# 1. Использовать ADR для решений сервиса BFF

Date: 2026-10-24

## Status

Accepted

## Context

Сервису BFF нужен локальный журнал решений, чтобы его архитектура развивалась независимо от общесистемных ADR и решений bounded contexts. Общесистемные требования продолжают храниться в корневом `docs/adr`, а решения, принадлежащие только BFF, не должны занимать место в этом журнале.

## Decision

Архитектурные решения сервиса BFF документируются в виде Architecture Decision Records в `boundaries/bff/docs/adr`. Для создания, нумерации и связывания записей используется [adr-tools](https://github.com/npryce/adr-tools); локальный журнал выбирается через `boundaries/bff/.adr-dir`.

## Consequences

Решения BFF получают собственную последовательную нумерацию и проходят ревью рядом с документацией и будущей реализацией сервиса. При этом потребуется явно различать локальные решения BFF и общесистемные решения проекта и ставить между ними относительные ссылки, когда они зависят друг от друга.
