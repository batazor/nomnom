# 2. Использовать Temporal для оркестрации заказов

Date: 2026-10-24

## Status

Accepted

## Context

Процесс заказа длится дольше одного синхронного запроса: он включает ожидания, таймеры и взаимодействие с контекстами ресторанов, доставки и платежей. Контекст `orders` должен координировать этот процесс и надёжно отражать результаты в состоянии заказа, не забирая ответственность за приготовление, доставку и платёжные операции у соответствующих bounded contexts.

## Decision

Использовать Temporal в контексте `orders` для оркестрации длительного процесса заказа, включая ожидания, таймеры и взаимодействие с другими контекстами.

Workflow относится к прикладному процессу. Доменные правила и инварианты заказа остаются независимыми от Temporal SDK.

«Прикладной процесс» описывает ответственность workflow, а не каталог. По [общесистемному ADR 6](../../../../docs/adr/0006-ddd-structure-inside-vertical-slices.md#входы-в-application) workflow и типы Activity payloads образуют Temporal-адаптер в `infrastructure/`: fulfillment workflow, охватывающий несколько слайсов, размещается в `boundaries/orders/infrastructure/temporal/`. Workflow не знает о Commands, Queries, handlers и модели `Order`. Activity преобразует свой payload в Command или Query и вызывает handler слайса; use case запускает workflow или передаёт ему Signal/Update через порт в `applications/`.

Внешние вызовы и операции с побочными эффектами выполняются через Activities. Повторяемые операции должны быть идемпотентными.

Конкретные шаги процесса, таймауты и правила компенсаций будут определены в соответствующих SDD-спецификациях. Это решение дополняет общесистемное разделение bounded contexts, зафиксированное в корневом ADR 2.

## Consequences

Temporal обеспечивает устойчивое выполнение длительных процессов, восстановление после сбоев, ожидания и таймеры. Temporal SDK остаётся в инфраструктурном адаптере `orders`, а `applications/` видит процесс только через порт, поэтому граница с независимой доменной моделью и handlers должна соблюдаться явно. Activities и интеграции потребуют продуманной идемпотентности, а эксплуатация Temporal и workers будет спроектирована отдельно; этим ADR исходный код, зависимости и инфраструктура не вводятся.
