# 3. Использовать Watermill для событийной интеграции orders

Date: 2026-10-24

## Status

Accepted

## Context

Общесистемный ADR 4 выбирает Apache Kafka как транспорт интеграционных событий, но оставляет выбор клиентской библиотеки за каждым bounded context. Для Go-контекста `orders` нужен согласованный способ публикации и обработки сообщений без прямой привязки прикладного кода к низкоуровневому Kafka API.

## Decision

Использовать [Watermill с адаптером `watermill-kafka`](https://watermill.io/pubsubs/kafka/) для публикации и обработки интеграционных событий через Apache Kafka в контексте `orders`.

Конкретные топики, контракты и схемы событий этим решением не определяются.

## Consequences

`orders` получает единый API для событийной интеграции и изолирует прикладной код от деталей Kafka-клиента. Одновременно Watermill и `watermill-kafka` становятся технологическими зависимостями контекста; обработчики должны учитывать повторную доставку, идемпотентность и ошибки публикации или обработки сообщений.
