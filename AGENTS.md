# Agent instructions

## Agent skills

### Issue tracker

Задачи ведутся в Linear workspace `bestnomnom`; проект выбирается по области задачи. См. `docs/agents/issue-tracker.md`.

### Triage labels

Используются стандартные labels Matt Pocock skills. См. `docs/agents/triage-labels.md`.

### Domain docs

Используется multi-context layout с общесистемными и контекстными ADR. См. `docs/agents/domain.md`.

## Порядок работы

Сначала внести все изменения задачи целиком, проверять (деплой, прогоны, тесты) — один раз в конце.
Не применять и не проверять каждый шаг по отдельности по ходу работы.

## Без фолбеков

Никаких фолбеков, деградаций и «безопасных» значений по умолчанию:

- обязательный конфиг пуст или невалиден — процесс падает на старте; не стартовать «частично» с отключёнными операциями, `Rejecting*`/`DenyAll*` и warning в логе;
- никаких режимов-заглушек (`simulated`, `unavailable`, `noop`) вместо реальных адаптеров и никаких in-memory адаптеров;
- никаких цепочек «нет X — возьми Y» (`?? "default"`, `|| "value"`, `getenv(..., "default")`, `| default` в helm) для конфига и данных; значение задаётся явно там, где оно нужно;
- нет данных или выбора — явная ошибка или пустое состояние, а не подстановка первого попавшегося;
- `switch` по конфигу: неизвестное значение — ошибка, не `default:` на запасную ветку.

## ADR: править, а не плодить

Новый ADR не создаётся, если решение уточняет, расширяет или меняет тему существующего ADR — правится существующий (решение, контекст, последствия) и связанная документация в `docs/`. Новый ADR — только для темы, которой нет ни в одном ADR. Перед созданием ADR найти связанные (`docs/adr/`, локальные `boundaries/*/docs/adr/`).
