# Spec Delta

## MODIFIED Requirements

### Requirement: Start Preparation начинает приготовление заказа из очереди
**ID:** FR-225

Start Preparation SHALL переводить заказ из `QUEUED` в `PREPARING` с `preparation_started_at` и `cook_id` и MUST атомарно записывать `PreparationStarted`. Cook SHALL выбираться автоматически: свободный Cook ресторана на линии с самым ранним последним назначением, никогда не назначенные — первыми. Без свободного Cook команда MUST отклоняться как `NoCookAvailable`; заказ остаётся в `QUEUED`, Outbox не меняется. Поведение повтора для заказа в `PREPARING` MUST задаваться явной политикой composition root: успешный no-op без бизнес-факта и без нового назначения Cook либо отказ как already in state.

#### Scenario: Кухня начинает приготовление
**ID:** AC-253

- **WHEN** сотрудник кухни начинает приготовление заказа из очереди, и на линии есть свободный Cook
- **THEN** заказ в `PREPARING` с `cook_id` этого Cook и в Outbox записан `PreparationStarted`

#### Scenario: Нет свободного повара
**ID:** AC-782

- **GIVEN** все Cook на линии заняты или линия пуста
- **WHEN** сотрудник кухни начинает приготовление заказа из очереди
- **THEN** операция отклоняется как `NoCookAvailable`, заказ в `QUEUED`, Outbox не меняется

#### Scenario: Выбор повара
**ID:** AC-783

- **GIVEN** на линии свободны Cook «Айгуль», назначенная 10 минут назад, и «Олег», назначенный 2 минуты назад
- **WHEN** сотрудник кухни начинает приготовление заказа
- **THEN** заказу назначена «Айгуль»

#### Scenario: Повтор при политике no-op
**ID:** AC-254

- **WHEN** политика повтора — no-op и приготовление уже начато
- **THEN** возвращается текущее состояние без нового `PreparationStarted`

#### Scenario: Повтор при строгой политике
**ID:** AC-255

- **WHEN** политика повтора — отказ и приготовление уже начато
- **THEN** операция отклоняется как already in state
