# Design

## Модель

- `Restaurant.timeZone` — IANA-пояс, обязателен в Register Restaurant, неизвестный — `INVALID_ARGUMENT`, не меняется после регистрации. Пояс города не меняется, поэтому копия пояса Market в ресторане не расходится с ним.
- `Restaurant.openingHours` — недельное расписание: по каждому дню недели список интервалов `{opens: "HH:MM", closes: "HH:MM"}` в местном времени. `closes ≤ opens` означает закрытие на следующий день (`18:00–02:00`). `opens = closes` запрещено.
- Интервалы недели, включая переход через полночь в следующий день и с воскресенья на понедельник, MUST NOT пересекаться; нарушение — `INVALID_ARGUMENT` с днём и интервалом.
- `SetOpeningHours(restaurant_id, weekly)` заменяет расписание целиком, требует `restaurant#manage`, увеличивает `version`. Integration Event не публикуется; кеш каталога обновляется по TTL, как при Update Restaurant.

## Моменты и перевод часов

Расписание хранится в местном времени, а все проверки работают с моментами. Интервал конкретной даты переводится в моменты в поясе ресторана:

- местное время в пропуске перевода (весной `02:30` не существует) переходит на первый момент после пропуска;
- неоднозначное местное время (осенью `02:30` бывает дважды) берётся по первому вхождению.

Поэтому в ночь перевода интервал `22:00–04:00` длится на час меньше или больше, и это верно: ресторан работает по часам на стене.

## Приём заказов

`accepting_orders(now) = isOpen ∧ ∃ интервал: opens_at ≤ now < closes_at`.

- Порт acceptance conditions вычисляет текущий интервал из документа ресторана и отдаёт его `opensAt`/`closesAt` в `RestaurantAcceptingOrders`; вне интервала — ближайшие границы, чтобы Specification вернула `outside_opening_hours`. Ничего не читается вне UoW.
- Ресторан без интервалов никогда не принимает заказы по расписанию.
- `next_opening_at` — начало ближайшего интервала после `now`, если ресторан сейчас вне расписания; при выключенном флаге не вычисляется (момент открытия неизвестен).
- List Restaurants по умолчанию: `accepting_orders(now)`. Хранимого признака «в расписании» нет: кеш каталога хранит расписание и вычисляет приём при чтении, как текущее ожидание кухни.
- Accept Order уже проверяет `RestaurantAcceptingOrders`, Place Order — открытость в catalog snapshot; оба получают расписание без новых правил.

## Migration

Документы ресторанов получают `timeZone: "Europe/Berlin"` (все существующие рестораны в Market `berlin`) и пустое расписание. Пустое расписание означает «не принимает»: подставлять «круглосуточно» запрещено. Демо-рестораны получают расписание из seed в kind; хранилища kind сбрасываются.

## UI

- Экран управления рестораном: таблица дней недели с интервалами, добавление и удаление интервала, сохранение целиком; ошибки пересечения у интервала.
- Каталог: ресторан вне расписания показан с «Откроется в HH:MM» (в его поясе), его меню доступно для просмотра, оформление недоступно.

## Риски

- После выкатки без seed все рестораны перестают принимать заказы. Seed и e2e меняются в том же change.
- Кеш каталога может показать «принимает» на TTL дольше: Accept Order и catalog snapshot Place Order проверяют расписание по документу, поэтому заказ вне расписания не пройдёт.
