# Design

## Context

Требования — в [spec.md](specs/customer-web-application/spec.md), мотивация — в [proposal.md](proposal.md).

Как устроено сейчас:

- **Предложение курьеру.** Перетаскивание сделано на нативном HTML5 DnD (`flow-board/board-dnd.tsx`). Источник — `article` карточки кухни, цель — строка свободного курьера в пуле (`pool-panel.tsx`). Мутацию `offerDeliveryToCourier` вызывает только `onDropOrder` в `courier-pool.tsx`. `useCourierPool()` возвращает `null` всем, кто не диспетчер (AC-798).
- **Кнопки во время запроса.** `Button` превращает `isPending` в нативный `disabled` (`shared/ui/button.tsx`). Chromium снимает фокус с отключённой кнопки. Кнопки пулов, «+» степпера и переключатель «Эмулятор» ставят `disabled` сами на время своего же запроса.
- **Обновление карточек.** Карточки доски перестраиваются по ответу мутации или по subscription: стадия меняется, карточка уходит. Нажатая кнопка размонтируется не сразу, а когда приходят данные.
- **Плашка корзины.** `cart-bar.tsx` возвращает `null`, как только форма оформления видна на экране.
- **Узкий экран.** У `.restaurant-layout` на узкой ширине нет шаблона колонок. Неявная колонка растягивается по min-content строки меню, примерно до 311px при доступных 236px. `.app-sheet { overflow: clip }` и `body { overflow-x: hidden }` прячут то, что не поместилось.
- **Язык.** `index.html` зашивает `lang="ru"`, а `I18nProvider` его не трогает.

## Goals / Non-Goals

**Goals:**

- Каждый сценарий спеки покрыт компонентным тестом. Исключение — reflow: jsdom не считает раскладку, поэтому он проверяется в браузере на 320px.
- Восстановление фокуса не отнимает фокус у пользователя, который уже перешёл в другое место.

**Non-Goals:**

- Замена нативного DnD на библиотеку с клавиатурным перетаскиванием. Альтернатива одним нажатием закрывает 2.1.1 и 2.5.7 проще.
- Общий менеджер фокуса на всё приложение.

## Decisions

### Предложение курьеру из меню на карточке заказа

На карточке кухни появляется кнопка «Предложить курьеру» с меню Headless UI (`Menu` из `shared/ui`). Условия показа те же, что у перетаскивания: пул доступен, заказ не в `RECEIVED`, курьер ему не назначен и не предложен (`useCourierOf` вернул `null`).

- **Пункты меню** — курьеры `AVAILABLE` без `offeredOrderId`.
- **Нет таких курьеров** — один отключённый пункт «Нет свободных курьеров». Так кнопка не прыгает при изменениях пула, а AC-1100 выполняется.
- **Одна логика для двух способов.** Вызов мутации и разбор problem code выносятся в хук `useOfferDelivery()` в `courier-pool.tsx`. Через него идут и `onDropOrder`, и меню. Ошибку меню показывает в существующем слоте ошибки карточки, ошибку перетаскивания — пул, как сейчас.

Альтернатива: кнопка «Предложить заказ» в строке свободного курьера. Отклонена: строке пришлось бы знать список заказов из колонки кухни. Меню на карточке повторяет направление перетаскивания (заказ → курьер), и логика остаётся там, где диспетчер смотрит на заказ.

### Ожидание через `aria-disabled`

- **`Button`.** При `isPending` ставит `aria-disabled="true"` вместо нативного `disabled` и игнорирует `onClick`. Стиль ожидания уже висит на `[data-pending]`.
- **`disabled`** остаётся нативным для состояний, которые известны до фокуса. Например, «−», когда убирать некого.
- **Где кнопка выключала сама себя.** Вызовы, которые ставили `disabled` на время своего же запроса, переходят на `isPending`: кнопки пулов «на линию», «снять», «+», «−» и отправка формы.
- **Предел количества.** Там, где кнопка упирается в предел своим же нажатием («+» и «Добавить» при количестве 99), — `aria-disabled` и игнорирование нажатия.
- **`Switch`.** Получает такой же `isPending` для переключателя «Эмулятор».

Альтернатива: везде заменить `disabled` на `aria-disabled`. Отклонена: отключённые заранее кнопки тогда попадут в порядок Tab без пользы.

### Восстановление фокуса, только когда он потерян

Колонки кухни и курьера запоминают последнее действие на карточке: `orderId` и позицию карточки в колонке. После перерисовки срабатывает effect.

1. Если `document.activeElement` — не `body`, ничего не делать: пользователь ушёл дальше или фокус уцелел.
2. Если карточка `orderId` ещё есть — фокус на её заголовок `board-card-head`.
3. Иначе — фокус на заголовок карточки, которая теперь стоит на той же позиции, то есть на следующую.
4. Иначе — на заголовок колонки с `tabIndex={-1}`.

После этого запомненное действие сбрасывается.

- **Взять заказ.** «Взять заказ» и «Подтвердить доставку» в колонке курьера работают так же. Целью для «Взять заказ» становится карточка доставки того же `orderId`.
- **Оформление заказа.** Доска запоминает, что заказ оформлен с клавиатуры. Когда в полосе заказов появляется чип нового заказа, фокус переходит на него. Срабатывает по тому же правилу «только если фокус на `body`».
- **Выбор ресторана.** Фокус ставится на заголовок ресторана с `tabIndex={-1}` при монтировании страницы ресторана, открытой выбором. При возврате «← Все рестораны» фокус ставится на карточку ресторана, из которого вернулись.
- **Плашка корзины.** Если форма оформления появилась на экране, а фокус внутри плашки, фокус сначала переносится на кнопку отправки формы — это то же действие с той же подписью, — и только потом плашка скрывается.

Почему правило «только если потерян». Данные приходят асинхронно, по ответу мутации или по subscription через секунды. Безусловная установка фокуса утащила бы его у пользователя, который уже работает в другой колонке.

Альтернатива: всегда фокус на заголовок колонки. Отклонена: в очереди из десяти заказов пользователь каждый раз проходил бы их заново.

### Reflow 320px исправляется в CSS

- `.restaurant-layout` на узкой ширине получает `grid-template-columns: minmax(0, 1fr)`.
- Строки корзины и остальные места, найденные проверкой в браузере, — так же: `minmax(0, …)` у колонок grid и перенос длинных названий.
- `body { overflow-x: hidden }` и `overflow: clip` у листа не трогаются: на них держатся sticky-части.

### `lang` ставит провайдер i18n

`I18nProvider` выставляет `document.documentElement.lang = locale` в effect при каждой смене локали. Из `index.html` атрибут `lang` удаляется: фиксированное значение в разметке — это значение по умолчанию, которое расходится с конфигом. Пустая или неизвестная локаль уже валит старт в runtime config, отдельной обработки не нужно.

## Risks / Trade-offs

- **Хрупкое правило фокуса.** Правило «только если фокус на `body`» зависит от того, что браузер при удалении узла с фокусом переносит его на `body`. Chromium, Firefox и Safari так и делают. Тесты в jsdom проверяют этот же сценарий.
- **Ожидающие кнопки в порядке Tab.** Кнопки с `aria-disabled` остаются в порядке Tab, и пользователь может нажать их ещё раз. Повторное нажатие игнорируется, это проверяется тестом AC-1102.
- **Меню внутри перетаскиваемой карточки.** Меню лежит внутри `article` с `draggable`. Нажатие на кнопку меню не начинает перетаскивание: drag стартует только при движении указателя. Порядок проверяется в браузере.
- **Непокрытые места переполнения.** Проверка на 320px может найти переполнение и в других экранах. Каждое найденное чинится в этом change, если причина та же — колонка grid или flex без `minmax(0, …)` и `min-width: 0`.
