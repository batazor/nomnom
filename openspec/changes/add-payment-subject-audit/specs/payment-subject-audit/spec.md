# Spec Delta

## ADDED Requirements

### Requirement: Раскрытие и забвение только для проверенного пользователя
**ID:** FR-751

`RevealPaymentRequesters` и `ForgetSubject` SHALL выполняться только для `Subject` вида `user`, подтверждённого user assertion разрешённого делегата, и только при наличии permission `reveal_subjects` или `forget_subjects`. Проверка MUST выполняться до чтения данных и до изменения ключей. Отказ или недоступность авторизации MUST отклонять запрос (fail closed).

#### Scenario: Вызов сервиса
**ID:** AC-1051

- **WHEN** сервис вызывает RPC без user assertion
- **THEN** запрос отклоняется `PERMISSION_DENIED`, SpiceDB не вызывается, данные не читаются

#### Scenario: Пользователь без права
**ID:** AC-1052

- **WHEN** пользователь без связи `auditor` вызывает RPC
- **THEN** запрос отклоняется `PERMISSION_DENIED`, запись в журнал аудита не создаётся

#### Scenario: Авторизация недоступна
**ID:** AC-1053

- **WHEN** проверка права завершается технической ошибкой
- **THEN** запрос отклоняется `UNAVAILABLE`, данные не раскрываются

#### Scenario: Нет причины
**ID:** AC-1054

- **WHEN** причина пуста или длиннее 200 символов
- **THEN** запрос отклоняется `INVALID_ARGUMENT`, данные не раскрываются

### Requirement: Раскрытие фиксируется до расшифровки
**ID:** FR-752

`RevealPaymentRequesters` SHALL возвращать операции `Payment` с автором и его статусом `known`, `forgotten` или `unknown`. Запись аудита на каждый открываемый `key_id` MUST быть зафиксирована до расшифровки. Если запись не удалась, идентификатор MUST NOT раскрываться.

#### Scenario: Раскрытие автора
**ID:** AC-1055

- **GIVEN** операция запрошена пользователем с активным ключом
- **WHEN** `auditor` запрашивает раскрытие с причиной
- **THEN** ответ содержит идентификатор со статусом `known`, журнал содержит автора запроса, `key_id`, `payment_id` и причину

#### Scenario: Сбой записи аудита
**ID:** AC-1056

- **WHEN** запись в журнал аудита завершается ошибкой
- **THEN** запрос завершается ошибкой, расшифровка не выполняется

#### Scenario: Открывать нечего
**ID:** AC-1057

- **GIVEN** авторы операций — сервисы, забытые пользователи или неизвестны
- **WHEN** `auditor` запрашивает раскрытие
- **THEN** ответ содержит их статусы, запись аудита не создаётся

### Requirement: Забвение атомарно с записью аудита
**ID:** FR-753

`ForgetSubject` SHALL очищать ключ пользователя и записывать действие в одной локальной транзакции. Идентификатор забываемого пользователя MUST NOT попадать в журнал аудита. Неизвестный пользователь MUST возвращать `forgotten = false` и записывать действие с исходом `no_key`.

#### Scenario: Забвение пользователя
**ID:** AC-1058

- **WHEN** `auditor` забывает пользователя с активным ключом
- **THEN** ключ очищен, журнал содержит автора, `key_id` и причину, но не идентификатор, следующее раскрытие показывает `forgotten`

#### Scenario: Сбой записи при забвении
**ID:** AC-1059

- **WHEN** запись в журнал аудита завершается ошибкой
- **THEN** ключ не очищается, запрос завершается ошибкой

### Requirement: Журнал аудита неизменяем
**ID:** FR-754

Хранилище SHALL разрешать только добавление записей `subject_key_audit`. `UPDATE` и `DELETE` MUST отклоняться на уровне схемы. Забвение MUST NOT менять записи, где пользователь был автором действия.

#### Scenario: Попытка изменить запись
**ID:** AC-1060

- **WHEN** выполняется `UPDATE` или `DELETE` строки журнала
- **THEN** база отклоняет операцию ошибкой

### Requirement: Обход через CLI закрыт
**ID:** FR-756

`payments-admin` MUST NOT раскрывать идентификатор пользователя и забывать пользователя. `subjects rewrap` SHALL требовать причину и записывать действие с `actor_kind = cli` и числом перешифрованных ключей.

#### Scenario: Перешифровка в журнале
**ID:** AC-1061

- **WHEN** оператор запускает `subjects rewrap` с причиной
- **THEN** журнал содержит запись `rewrap` без `actor_id` и с `affected_keys`

### Requirement: GraphQL-мутации аудита
**ID:** FR-757

BFF SHALL предоставлять мутации `revealPaymentRequesters` и `forgetSubject`, вызывающие RPC с user assertion текущего пользователя. Раскрытие MUST быть мутацией и MUST NOT кешироваться.

#### Scenario: Вызов без входа
**ID:** AC-1065

- **WHEN** мутация вызывается без сессии пользователя
- **THEN** запрос отклоняется, RPC `payments` не вызывается

### Requirement: Экран аудита
**ID:** FR-758

UI SHALL предоставлять экран раскрытия и забвения вошедшему пользователю. Забвение MUST требовать причину и подтверждение повторным вводом идентификатора. Раскрытые данные MUST NOT сохраняться в кеше запросов и браузерном хранилище.

#### Scenario: Подтверждение забвения
**ID:** AC-1062

- **WHEN** повторно введённый идентификатор не совпадает с первым
- **THEN** мутация не отправляется

#### Scenario: Данные не сохраняются
**ID:** AC-1063

- **WHEN** оператор получил результат раскрытия и покинул экран
- **THEN** результата нет в кеше запросов и в браузерном хранилище

### Requirement: Идентификатор не попадает в логи
**ID:** FR-759

Идентификатор пользователя из `ForgetSubject` и ответа раскрытия MUST NOT попадать в логи BFF, gateway и `payments`.

#### Scenario: Маркер в логах
**ID:** AC-1064

- **WHEN** сценарий e2e забывает пользователя с уникальным идентификатором
- **THEN** этого значения нет в логах BFF, gateway и `payments` за время сценария

### Requirement: Причина обязательна для каждого действия
**ID:** FR-755

Каждая запись журнала SHALL содержать причину длиной от 1 до 200 символов и момент записи. Действие без причины MUST отклоняться схемой, даже если проверка use case пропущена.

#### Scenario: Запись без причины
**ID:** AC-1066

- **WHEN** в журнал вставляется строка с пустой причиной
- **THEN** база отклоняет операцию ошибкой
