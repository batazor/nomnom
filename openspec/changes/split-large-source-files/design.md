# Design

## Context

См. `proposal.md`. В репозитории четыре языка с разными нормами модулей: в Go файл не является единицей API (пакет — да), в Rust модуль равен файлу, а тесты часто встроены; в TypeScript и Python модуль равен файлу, и внешние импорты ссылаются на путь.

## Decisions

### 1. Критерий — ответственность

Файл делится, если в нём живут части, которые меняются по разным причинам и читаются независимо: несколько компонентов инфраструктуры, разные секции конфигурации, модель и её адаптеры, production-код и объёмные тесты. Цельный файл — один агрегат с его поведением, одна таблица, один адаптер — остаётся целым независимо от длины. Числовых порогов нет: счётчик строк не говорит о связности, а подгонка под порог ухудшает её.

### 2. Как делить

- **Go**: один пакет — несколько файлов по теме. Например, `memory/store.go` → тип и UoW, `orders`, `inbox`, `outbox`, read models; `domains/order/order.go` → агрегат и конструктор, отмена, факты, события. Тесты делятся по тем же темам. Экспортируемые имена не меняются.
- **Rust**: `#[cfg(test)] mod tests;` с телом в `<module>/tests.rs`; `mod.rs` с несколькими компонентами — подмодули с `pub use`, чтобы пути `crate::…` у потребителей не изменились.
- **TypeScript/Python**: модуль делится на соседние модули; исходный модуль реэкспортирует публичные имена, если на него ссылаются извне, иначе импорты обновляются.

### 3. Порядок исполнения

Исполнение идёт по контексту, одним исполнителем на контекст, после structural changes этого контекста (fulfillment в `orders`, границы слайсов в `delivery`, переименование в `restaurants`), чтобы не делить файлы, которые эти changes удалят или переименуют. `payments`, `bff` и `ui` от них не зависят.

## Risks / Trade-offs

- [Механическое разбиение ухудшит связность] → делить только по ответственности; разбиение, которое разносит один класс или одну модель по файлам без причины, откатывается.
- [Конфликты с параллельными сессиями] → исполнитель трогает только файлы своего контекста и работает на отдельной ветке.

## Migration Plan

Разбиение по контекстам; после каждого — тесты и линтеры контекста. Rollback — revert по контексту.
