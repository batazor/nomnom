# Design

## Context

См. `proposal.md`. В репозитории четыре языка с разными нормами модулей: в Go файл не является единицей API (пакет — да), в Rust модуль равен файлу, а тесты часто встроены; в TypeScript и Python модуль равен файлу, и внешние импорты ссылаются на путь.

## Decisions

### 1. Пороги

| Вид | Порог |
| --- | --- |
| production | 300 строк |
| тест | 500 строк |

Тестом считается файл по соглашению языка: `*_test.go`; `tests.rs`, файлы в `tests/` и `benches/`; `*.test.ts`, `test/**`; `test_*.py`, `tests/**`. Встроенные тесты Rust считаются частью production-файла — поэтому их выносят. Пороги одинаковы для всех языков: так правило проще помнить; разница production/тест — потому что табличные тесты естественно длиннее.

### 2. Что исключено

Сгенерированный код (`*.pb.go`, `*_grpc.pb.go`, `wire_gen.go`, `gen/`, `generated/`, `*_pb.js`, `*_pb.d.ts`, `src/shared/graphql/generated/`), зависимости и сборка (`node_modules`, `target*`, `dist`, `.venv`, `__pycache__`), fixtures (`tests/identity/fixtures`). Allowlist — для файлов, которые нельзя разумно разбить (например, таблица переходов FSM), с причиной в той же строке.

### 3. Проверка

`ops/checks/file-size.sh [paths…]` проходит по `git ls-files` (только отслеживаемые файлы), применяет исключения и allowlist, печатает нарушителей `<lines> <limit> <path>` и завершается с кодом 1, если они есть. Цель `make check-file-size` в корневом `Makefile` вызывает его для `boundaries/`. Скрипт без зависимостей кроме POSIX shell и `awk`.

### 4. Как делить

- **Go**: один пакет — несколько файлов по теме. Например, `memory/store.go` → `store.go` (тип и UoW), `orders.go`, `inbox.go`, `outbox.go`, `read_models.go`; `domains/order/order.go` → `order.go` (агрегат и конструктор), `cancellation.go`, `facts.go`, `events.go`. Тесты делятся по тем же темам. Экспортируемые имена не меняются.
- **Rust**: `#[cfg(test)] mod tests;` с телом в `<module>/tests.rs`; крупные `mod.rs` — подмодули с `pub use` в `mod.rs`, чтобы пути `crate::…` у потребителей не изменились.
- **TypeScript/Python**: модуль делится на соседние модули; исходный модуль реэкспортирует публичные имена, если на него ссылаются извне, иначе импорты обновляются.

### 5. Порядок исполнения

Исполнение идёт по контексту, одним исполнителем на контекст, после structural changes этого контекста (fulfillment в `orders`, границы слайсов в `delivery`, переименование в `restaurants`), чтобы не делить файлы, которые эти changes удалят или переименуют. `payments`, `bff`, `ui` и скрипт проверки не зависят от них.

## Risks / Trade-offs

- [Механическое разбиение ухудшит связность] → делить по ответственности, а не по счётчику строк; если файл — одна неделимая таблица, он идёт в allowlist с причиной.
- [Конфликты с параллельными сессиями] → исполнитель трогает только файлы своего контекста, проверяет `git status` перед каждым файлом и не переформатирует чужое.

## Migration Plan

1. Скрипт, allowlist, цель Makefile; запуск даёт список нарушителей.
2. Разбиение по контекстам; после каждого — тесты и линтеры контекста.
3. `make check-file-size` проходит. Rollback — revert по контексту.
