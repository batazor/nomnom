# restaurant-menu Specification

## Purpose
Определяет, как авторизованный управляющий создаёт меню ресторана и управляет Menu Item, их ценами и доступностью, и как клиенты получают актуальное меню.

## Requirements

### Requirement: Изменения меню авторизуются по ресторану
**ID:** FR-210

Система SHALL проверять право subject управлять меню конкретного ресторана до загрузки и изменения меню. Отказ или ошибка authorization MUST оставлять меню и Outbox без изменений.

#### Scenario: Subject без права добавляет блюдо
**ID:** AC-220

- **WHEN** subject без права управления меню ресторана добавляет Menu Item
- **THEN** операция отклоняется как permission denied и меню не меняется

### Requirement: Create Menu создаёт единственное меню ресторана
**ID:** FR-211

Create Menu SHALL создавать пустое меню, принадлежащее существующему ресторану. У ресторана MUST быть не больше одного меню; повторное создание MUST отклоняться как already exists.

#### Scenario: Создание меню
**ID:** AC-221

- **WHEN** управляющий создаёт меню для ресторана без меню
- **THEN** создаётся пустое меню этого ресторана и возвращается его идентификатор

#### Scenario: Меню уже существует
**ID:** AC-222

- **WHEN** управляющий повторно создаёт меню для того же ресторана
- **THEN** операция отклоняется как already exists

#### Scenario: Ресторан не найден
**ID:** AC-223

- **WHEN** меню создаётся для несуществующего ресторана
- **THEN** операция отклоняется как not found

### Requirement: Цена Menu Item — точная неотрицательная сумма в валюте
**ID:** FR-212

Цена Menu Item SHALL задаваться точным десятичным представлением суммы и трёхбуквенным кодом валюты. Отрицательная, неточная или нечисловая сумма и некорректный код валюты MUST отклоняться как invalid argument.

#### Scenario: Отрицательная цена
**ID:** AC-224

- **WHEN** управляющий задаёт Menu Item цену `-1.00`
- **THEN** операция отклоняется как invalid argument и меню не меняется

#### Scenario: Точная десятичная цена
**ID:** AC-225

- **WHEN** управляющий задаёт цену `0.10` в `EUR`
- **THEN** сохраняется ровно `0.10 EUR` без двоичного округления

### Requirement: Add Menu Item добавляет блюдо в меню
**ID:** FR-213

Add Menu Item SHALL создавать Menu Item с идентификатором, уникальным в меню, непустым названием, необязательным описанием, ценой и исходной доступностью. По умолчанию новое блюдо MUST быть доступным.

#### Scenario: Добавление блюда
**ID:** AC-226

- **WHEN** управляющий добавляет блюдо с названием и ценой
- **THEN** в меню появляется доступный Menu Item и возвращается его идентификатор

#### Scenario: Меню отсутствует
**ID:** AC-227

- **WHEN** блюдо добавляется ресторану без меню
- **THEN** операция отклоняется как not found

### Requirement: Update Menu Item меняет основные данные блюда
**ID:** FR-214

Update Menu Item SHALL менять название, описание, цену и доступность существующего Menu Item в пределах инвариантов меню. Изменение MUST NOT затрагивать snapshot уже оформленных `Order`. Если меняется доступность, факт `MenuItemAvailabilityChanged` MUST сохраняться в Outbox атомарно с меню.

#### Scenario: Изменение цены
**ID:** AC-228

- **WHEN** управляющий меняет цену существующего блюда
- **THEN** блюдо имеет новую цену, остальные поля не изменились, бизнес-факт не публикуется

#### Scenario: Неизвестное блюдо
**ID:** AC-229

- **WHEN** управляющий меняет несуществующий Menu Item
- **THEN** операция отклоняется как not found

### Requirement: Set Menu Item Availability меняет только доступность
**ID:** FR-215

Set Menu Item Availability SHALL менять доступность Menu Item без изменения остальных данных меню и MUST атомарно записывать `MenuItemAvailabilityChanged` в Outbox. Установка уже действующего значения SHALL быть успешной без нового бизнес-факта.

#### Scenario: Блюдо временно недоступно
**ID:** AC-230

- **WHEN** управляющий делает доступное блюдо недоступным
- **THEN** блюдо недоступно, остальные данные не изменились, в Outbox записан `MenuItemAvailabilityChanged`

#### Scenario: Повтор того же значения
**ID:** AC-231

- **WHEN** доступность устанавливается в уже действующее значение
- **THEN** операция успешна без изменения версии меню и без записи в Outbox

### Requirement: Get Menu возвращает актуальное меню
**ID:** FR-216

Get Menu SHALL возвращать актуальные Menu Item ресторана с названием, описанием, ценой и доступностью без изменения состояния. Результат MUST NOT использоваться как snapshot оформленного заказа.

#### Scenario: Меню с блюдами
**ID:** AC-232

- **WHEN** клиент запрашивает меню ресторана
- **THEN** возвращаются все Menu Item с текущими ценами и доступностью

#### Scenario: Меню отсутствует
**ID:** AC-233

- **WHEN** клиент запрашивает меню ресторана без меню
- **THEN** запрос отклоняется как not found

### Requirement: Get Menu доступен по gRPC
**ID:** FR-493

`restaurants` SHALL публиковать RPC `GetMenu(restaurant_id)`, возвращающий Menu Item с названием, описанием, ценой и доступностью по правилам FR-216, без authorization. Отсутствующее меню MUST возвращаться `NOT_FOUND`.

#### Scenario: Меню по gRPC
**ID:** AC-561

- **WHEN** вызывающий запрашивает `GetMenu` ресторана с опубликованным меню
- **THEN** ответ содержит все Menu Item с текущими ценами и доступностью
