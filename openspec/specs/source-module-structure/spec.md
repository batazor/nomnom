# source-module-structure Specification

## Purpose
Определяет, как исходные модули приложений делятся на файлы: по ответственности, а не по размеру, без изменения поведения и публичных API.

## Requirements

### Requirement: Модули делятся по ответственности без изменения поведения и API
**ID:** FR-489

Файл, в котором смешаны несвязанные ответственности, SHALL делиться по смыслу; цельный файл MUST NOT делиться только из-за длины. Разбиение MUST NOT менять поведение, экспортируемые имена и пути импорта, которыми пользуются другие модули, кроме случаев, когда все потребители обновлены в том же изменении. Тесты и линтеры контекста SHALL проходить после разбиения.

#### Scenario: Пакет Go разбит на файлы
**ID:** AC-554

- **WHEN** `orders/slices/order/infrastructure/memory/store.go` разбит на несколько файлов пакета `memory` по темам
- **THEN** экспортируемые имена пакета не изменились, а `go test ./...` и `make lint` в `orders` проходят

#### Scenario: Цельный агрегат не делится
**ID:** AC-553

- **WHEN** файл содержит один агрегат с его поведением и событиями
- **THEN** агрегат остаётся в своём файле; выносятся только независимые части вроде событий и ошибок, если они читаются отдельно
